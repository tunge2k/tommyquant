## 0. 术语与口径（先对齐，避免误读）

**本项目是现金账户，不是保证金账户。**

- 引擎 `etf_rebalance.ETFReBalanceStrategy` 中 `self.cash` 严格不允许为负，无融资融券、无保证金、**不存在强制平仓或追缴保证金**（见 [etf_rebalance.py](../etf_rebalance.py) `_buy` / `_deviation_check`）。
- 本系统中「账户余额不足」的实际表现是：**4% 偏差补仓被可用现金约束跳过**（`cash_short_skips` 计数），即「价格跌了、该按网格补仓，但没钱补」——低买高卖规则失效，而不是爆仓。
- 因此本文把用户口径的「**剩余可用保证金比例**」定义为：

  ```
  可用现金比例 = 成交后现金(cash_after) / 当日总资产(curve.value)
  ```

  该比例 = 0 表示「已满仓、无任何补仓能力」；比例越高，抗连续下跌能力越强。

数据字段位置：成交流水 `cash_after` 由 [etf_rebalance.py](../etf_rebalance.py) `_record()` 写入；总资产取 payload 的 `curve[].value`（现金 + 收盘持仓市值）。

## 2. 成因分析

1. **仓位与网格不匹配（主因）**：95% 目标仓位 → 现金垫仅 5%；而单次 5% 网格补仓需求 ≈ 持仓市值 5% ≈ **总资产 4.75%**，再叠加 11.1 bp 成本，一次补仓就把现金垫耗尽。
2. **单标的（top_n = 1）**：没有其它标的的卖出回款可周转，同一天「先卖后买」的缓冲也不存在（只有涨了才卖）。
3. **连续下跌序列**：下跌时网格连续触发补仓，但现金只出不进 → 从第 2 次下跌起全部变为 `cash_short_skips`（109 次跳过即来源于此）。
4. **现金垫无下限保护**：引擎按「可用现金全额补」执行，不保留最低现金垫，因此每次都是「补到余额近 0」。

结论：在 `weight_fraction=0.95` 下，「跌了补仓」只能兑现约 1 次，之后低买高卖规则事实上失效。

## 3. 三类下跌情景与操作方案

阈值口径与引擎一致：**偏离 = 当前持仓市值 / 市值中枢 - 1**（`_deviation_check`，中枢为初始建仓/最近一次再平衡时的目标市值）。现金比例 = 可用现金 / 总资产。

| 情景 | 定义（相对市值中枢） | 现金比例参考 | 操作方案 |
|---|---|---|---|
| **小幅下跌** | -5% ~ -10% | > 3% | ① 允许网格正常触发补仓；② 分批执行：单次补仓 ≤ 可用现金的 1/2；③ 不改变目标仓位；④ 补仓后记录现金比例，低于 3% 即转入「中度」处置 |
| **中度下跌** | -10% ~ -20% | 0.5% ~ 3% | ① 只补 1 次且用尽可用现金（优先保证网格成交，避免「挂了不成交」）；② 随后**暂停网格补仓**，等卖出触发回款；③ 可选将 `weight_fraction` 95% → 85%（按当前总资产 5.39M 计，释放约 **53.9 万元** 现金垫）；④ 每月复核一次现金比例 |
| **极端下跌** | ≤ -20%，或回撤达到历史极值 -24.48% | < 0.5% | ① **停止一切补仓**（不再做「摊低成本」的无效动作）；② 按项目规则「趋势止损优先级最高」执行——MA30 走弱 / 绝对动量转弱即**整仓清仓**；③ 若未触发止损，则一次性降仓至 75% 完成再平衡（释放 20% 总资产现金）；④ 禁止融资、禁止借钱补仓 |

> 小额下跌（-5% 以内）不构成补仓信号，属网格中性区间；单笔成交额 < max(3000 元, 持仓市值 0.5%) 视为碎单，不交易。

## 4. 阈值 / 优先级 / 成本 / 对冲效果矩阵

以当前规模（总资产约 5.39M、`weight_fraction` 可变）测算单次补仓资金需求与现金垫的倍数关系：

| 目标仓位 | 现金垫（占总资产） | 单次 5% 网格补仓需求 | 现金垫 / 单次需求 | 可支撑补仓次数 |
|---|---|---|---|---|
| 95%（当前） | 5.0% | 4.75% | **1.05** | **1 次** |
| 90% | 10.0% | 4.50% | 2.2 | 2 次 |
| 85% | 15.0% | 4.25% | 3.5 | 3 次 |
| 75% | 25.0% | 3.75% | 6.7 | 6 次以上 |

| 操作 | 触发阈值 | 优先级 | 预估成本（按 11.1 bp） | 对冲 / 缓解效果 |
|---|---|---|---|---|
| 趋势止损清仓 | MA30 走弱 / 绝对动量转弱（项目规则最高优先级） | **P0** | 卖出约 539 万 × 11.1 bp ≈ **5,983 元** | 直接切断继续下跌敞口，是唯一能限制尾部损失的动作 |
| 降目标仓位（95%→85% 或 75%） | 现金比例 < 1% 且仍在下跌，或回撤 > 20% | **P0** | 卖出释放额 × 11.1 bp（95%→85% 约 599 元/10 万） | 现金垫从 5% 提升到 15%，补仓能力 ×3.5，但会放弃部分反弹弹性 |
| 分批补仓（每批 ≤ 可用现金 1/2） | 小幅下跌 -5%~-10% 且现金比例 > 3% | **P1** | 约 25 万 × 11.1 bp ≈ **278 元/次** | 把 1 次机会拆成 2 次，显著降低「一次补光后二次下跌无法应对」的概率 |
| 全额单次补仓 | 中度下跌 -10%~-20% 且现金比例 0.5%~3% | **P1** | 单次约 20~30 万，成本 220~330 元 | 维持网格成交率；但补完后现金约 0，必须转入 P2 |
| 暂停网格补仓 | 现金比例 < 0.5% | **P2** | 0 | 避免无效尝试（109 次跳过的直接来源），把决策权交回趋势止损 |
| 提前降低仓位（预防） | 建仓前 / 每季度复核 | **P2** | 一次性调仓成本 ≈ 600 元/10 万 | 从根本上把补仓成功率从 28% 提升到接近 100%（85% 仓位） |

> 成本口径：本次回测 133 笔成交合计成本 25,201.13 元，成交额 22,704,423.57 元，即 **11.1 bp/笔均**（含佣金、过户费、滑点、冲击成本；ETF 无印花税）。相对 +439% 的总收益，交易成本不构成主要风险，**真正的风险是「没钱补仓导致规则失效」而非手续费**。

## 5. 当前可提前执行的风险预防措施（无需等触发的动作）

1. **下调目标仓位**：把 `weight_fraction` 从 95% 调到 **85%~90%**（实测见 4.1：85% 补仓放弃 0 次，90% 仅 1 次，95% 为 76 次）。这是唯一能从根上解决余额不足的措施。
2. **设定现金垫硬下限**：任何补仓后现金比例不得低于 **3%**；触及即暂停网格，等卖出回款。
3. **补仓分批化**：单次补仓不超过可用现金 1/2，保留二次应对能力。
4. **建立余额监控**：页面已显示「资金不足跳过 N 次」摘要（[streamlit_app.py](../streamlit_app.py) `_render_etf_rebalance_validation`）；建议人工在此计数持续增长时立即检查现金比例，而不是等到 0%。
5. **再平衡前先查现金**：每次定期再平衡（当前 1 年）执行前，先核对「现金垫 / 单次补仓需求 ≥ 2」这一条件是否成立，不成立则先降仓。
6. **不接受外部杠杆**：不为补仓引入融资、借贷或保证金账户；本策略的最大回撤 -24.48% 已在满仓状态下测出，加杠杆会把「补仓失效」升级为「真实强平」。
7. **单标的风险分散**：`top_n = 1` 时全部资金押注 `sh513100`；若希望保留低买高卖能力，可考虑 `top_n ≥ 2`，用另一标的的卖出回款提供补仓现金。

## 7. 已落地的自动化机制（2026-11-28）

本章的应对方案已部分工程化，实现见 [etf_rebalance.py](../etf_rebalance.py) `_apply_cash_guard()`：

| 项 | 实现 |
|---|---|
| 预警阈值 | 默认 **4 ×** 单次偏差调仓所需资金（= 市值中枢 × 网格阈值），可配置 1~10 倍 |
| 监控频率 | 逐日（收盘撮合后），无需人工干预 |
| 触发条件 | ① 当日有卖出调仓（4% 偏差 / 定期再平衡）；② 可用现金 < 预警阈值 |
| 执行动作 | 在原计划卖出量之外**额外加卖**，把现金补回预警线 |
| 防过度卖出 | 额外量 ≤ 原计划卖出量 × `cash_guard_max_extra`（默认 50%）；且不超过现金缺口；且至少保留 1 手 |
| 审计记录 | `meta.cash_guard_log`：日期 / 标的 / 触发时余额 / 阈值 / 单次调仓需求 / 倍数 / 原计划-额外-实际股数 / 额外比例 / 目标仓位 / 执行后仓位 / 执行后余额与现金比例 |
| 规则校验 | `validate_result` 的「现金保护额外卖出≤上限」校验项 + `tests/test_etf_rebalance.py::CashGuardTest` |

实测（与第 1 章同一组参数，本地同源数据重跑）：触发 **34 次**、额外卖出 **168.4 万元**、
期末现金 88 → 189 元；总收益 363.42% → 361.61%、最大回撤 -29.76% → -29.96%、
补仓跳过 86 → 94 次。结论：该机制**抬高卖出日的现金水位**，但只在卖出日补足，
深跌段仍会补仓失败——所以它是缓解手段，第 5 章「下调目标仓位」仍是根治措施。


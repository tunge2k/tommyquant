# 全市场 ETF 月度动量策略（VectorBT 独立回测）

> 对应实现：`vectorbt_etf_backtest.py`。该脚本独立运行，不修改现有 `MarketCapStrategy`，也不叠加 MA30、估值、止损等未在本策略中定义的条件。

## 1. 策略口径

1. **信号时点**：每月最后一个交易日收盘后，使用当时已经可获得的数据完成全市场 ETF 筛选。
2. **执行时点**：下一交易日开盘成交，避免用当月收盘信号在同一收盘价成交的未来函数。
3. **候选范围**：数据库中全部场内 ETF，不使用固定候选池；指定货币 ETF 只承担避险/剩余资金管理，不参与风险资产动量排名。
4. **过滤顺序**：
   - 基金规模 `< 1 亿元`：剔除；
   - 截止信号日已有清盘、终止、合并公告：剔除；
   - 近 20 个交易日日均成交额 `< 5000 万元`：剔除。原规则未给成交额数值和窗口，因此二者作为顶部参数，默认分别为 20 日、5000 万元；
   - 首个行情日至信号日不足 182 个自然日：剔除。若数据库完整覆盖上市首日，即等价于“上市满半年”；若历史被截断，该处理只会更保守，不会提前纳入；
   - 跨境 ETF 溢价率 `> +1.5%`：剔除；普通 ETF 不校验溢价。跨境属性按基金名称关键词识别，港股/QDII 也按跨境处理；名称缺失时按跨境口径校验，防止漏检；
   - 60 个交易日复权市场价收益率 `< 0`：剔除。收益率为 0 不违反原规则，予以保留。
5. **排序选取**：按 60 日收益率降序，代码升序用于同分时的稳定排序。有效标的数不少于 N 时取前 N；不足 N 时全取；为空时风险资产仓位为 0，资金转入货币 ETF。
6. **权重**：默认动量加权，单只权重为自身 60 日收益率/选中标的收益率总和；顶部切换为 `equal` 即等权。所有得分均为 0 时退化为等权，避免除零。
7. **目标仓位**：风险资产合计为总资产的 75%，整体容差为 ±4%，即 71%–79%。
8. **调仓**：
   - 本次集合与上次不同：可交易的旧标的全部卖出，新集合直接配置到目标权重，不受 71%–79% 容差限制；
   - 集合相同：仅当风险资产市值占比低于 71% 或高于 79% 时回到 75%，区间内不调整风险资产；
   - 每次调仓后的剩余资金配置到默认货币 ETF；不足 100 份或不足以覆盖最低佣金的零头保留现金。
9. **无有效标的**：不持有风险 ETF，资产进入货币 ETF；货币 ETF 本身仍按 100 份整数倍交易并计成本。

## 2. 字段与数据源

默认读取项目 SQLite：`data/stock.db`。不联网下载数据，因此回测结果完全取决于库内历史覆盖。

| 用途 | 表与字段 | 口径 |
|---|---|---|
| 市场价、开盘执行价 | `daily_bar.open / close` | 场内市场价格，不是基金单位净值 |
| 真实成交额 | `daily_bar.amount` | 元；滚动计算历史日均成交额，不使用成交量替代 |
| 真实基金规模 | `etf_capital.market_scale` | 元；不是用价格 × 股票流通股本推算 |
| 跨境溢价率 | `etf_quote_ext.premium_ratio` | 百分数，1.5 表示 1.5%；不拿单位净值或价格字段混用 |
| 基金名称 | `etf_name.name` | 仅用于识别跨境属性 |
| 分红复权事件 | `etf_dividend.date / cum_div` | 除息日与累计每份分红，用于复权市场价收益 |
| 清盘/终止/合并公告 | 可选 `data/etf_termination_events.csv` | 字段：`symbol,ann_date,event_type`；公告日之后持续剔除 |

若数据库存在 `etf_termination_event(symbol,ann_date,event_type)` 表，也会自动读取。当前项目库没有公告表，因此脚本会明确输出警告；提供上述 CSV 后即可执行真实公告过滤。

### 缺失数据处理

- 规模、成交额、上市时长、动量的当期值缺失：该标的当期**不通过**，不以当前值回填历史。
- 跨境（含名称无法识别而按跨境保守处理）的溢价缺失：当期不通过；普通 ETF 不做溢价校验。
- 规模和溢价仅允许最多沿用 5 个交易日，超过后视为缺失，防止长期沿用旧值。
- 公告数据源完全缺失时，默认在数据质量报告中标记“公告过滤不完整”并继续运行；命令行加 `--strict-data` 则直接终止。该开关不会伪造公告，只是明确选择是否接受这一数据局限。

## 3. 成本、复权与交易约束

- 默认佣金率万分之一、单笔最低 0.2 元、ETF 印花税为 0、单边滑点万分之五，均在脚本顶部修改。
- VectorBT 原生的 `fees + fixed_fees` 不能表达 `max(成交额×佣金率, 最低佣金)`。脚本因此按每笔实际滑点后成交额预先计算最低佣金，并以 `fixed_fees` 矩阵逐笔传入，`fees=0`，实现精确成本。
- 所有订单按 100 份取整；资金不足时逐手递减，不允许负债买入。
- 分红/份额折算：对市场价格做后复权，使动量和净值包含分红、折算影响；执行与估值统一使用复权市场价。VectorBT 不原生处理 ETF 现金分红，这是采用复权价的原因。单位净值 `unit_nv` 只用于数据核对，不参与动量或成交。

## 4. VectorBT 局限与变通位置

1. **动态全市场筛选**：原生 `from_signals` 不适合在每个月末执行带历史横截面数据的全市场筛选。变通：在 `screen_universe()` 中逐月用 Pandas 完成过滤与排序，再生成订单。
2. **集合变化、整体仓位容差、货币 ETF 剩余资金配置**：固定信号矩阵无法直接表达。变通：`build_orders()` 维护上一期集合和预期持仓，生成带符号的目标股数差额订单。
3. **真实交易时段**：信号在月末收盘生成，订单写入下一交易日开盘价格矩阵，由 `Portfolio.from_orders()` 执行。
4. **最低佣金**：如上所述，用逐笔 `fixed_fees` 替代原生比例费率的近似表达。
5. **停牌/缺开盘价**：不制造可成交价格。旧标的缺开盘价时无法卖出并记录跳过；新标的缺开盘价时不买入，资金留在货币 ETF/现金。估值使用最近有效收盘价并明确标记为估值填充，不作为成交价。

## 5. 运行与输出

```bash
python -m pip install -r requirements.txt
python vectorbt_etf_backtest.py --start 2016-01-01 --weighting momentum --top-n 5
# 等权版本
python vectorbt_etf_backtest.py --weighting equal
# 公告数据不完整时也要求立即失败
python vectorbt_etf_backtest.py --strict-data
```

输出目录默认 `output/vectorbt_etf/`：

- `summary.json`：收益、回撤、夏普、订单数及参数；
- `daily_equity.csv`：每日权益、现金、风险仓位；
- `orders.csv`：脚本生成的逐笔目标订单与成本；
- `selection_log.csv`：每月过滤数量、入选代码和权重；
- `vectorbt_orders.csv`：VectorBT 实际订单记录；
- `data_quality.json`：字段覆盖和缺失警告；
- `equity.png`：权益曲线与风险仓位图。

## 6. 注意事项

- 本策略与项目现行“周 MA30/止损/跨境-only”策略是不同规则集，脚本没有复用那些过滤条件。
- 回测长度不等于有效交易长度；早期跨境 ETF 数量少、规模和成交额数据缺失时，会按规则空仓到货币 ETF。
- 本次本地验证时，`daily_bar` 覆盖 2020-01-02 至 2026-11-19，但 `etf_capital` 与 `etf_quote_ext` 仅有 2026-11-10 至 2026-11-19 的少量记录，且没有公告表。因此本地长区间结果主要反映货币 ETF 避险持仓，不能当作完整策略历史业绩；补齐历史规模、溢价和公告后再用于研究。
- 名称关键词只决定“是否校验溢价”，不额外限制只能投资跨境 ETF。
- 月度信号日至下一开盘日之间若出现新公告，而数据源只有日期没有发布时间，无法进一步细分盘中可见性；统一按公告日收盘后可见处理。

> 文档基线：2026-11-17
> 对应代码：`streamlit_app.py` / `backtest_engine.py` / `fast_backtest.py` / `data_store.py` / `data_manager.py` / `news_fetcher.py` / `update_worker.py`

## 1. 项目定位

**托米量化（TommyQuant）** 是一个自托管的 A 股多策略量化研究平台，运行在家庭 NAS 的单个 Docker 容器内，覆盖：

```
数据采集 → 因子计算 → 策略回测 → 每日选股 → 模拟持仓 → 资讯聚合
```

定位边界：

- 是**研究工具**，不是交易系统：不接券商接口、不下实盘单。
- 是**个人自用系统**：单用户、无权限体系、无多租户。
- 数据与结论**仅用于学习研究**，不构成投资建议。

---

## 2. 目标

### 2.1 产品目标

1. 一个容器同时提供 Web 界面与后台数据更新，NAS 上零手工运维。
2. 回测结果可重复：相同参数 + 相同数据必须命中缓存并返回完全一致的结果。
3. 策略可插拔：新增一个函数式策略不需要改引擎、不需要改数据层。
4. 覆盖全市场：全部 A 股 + ETF，而不是抽样验证。
5. 数据说话：所有绩效结论可在界面回溯到资金曲线与逐笔交易。

### 2.2 非功能目标与当前达成情况

| 维度 | 目标 | 当前实现 | 状态 |
|---|---|---|---|
| 行情实时性 | 端到端 < 5 秒 | 持仓与全球行情由浏览器直连东方财富 `push2`，1–2 秒轮询 | 达成 |
| 首次可用 | 空库自动就绪 | Worker 启动检测空库 → 全量下载 A 股 + ETF + 财务 | 达成 |
| 回测打开速度 | 参数不变时秒开 | SQLite `backtest_cache` + 数据指纹失效 + 因子矩阵磁盘缓存 | 达成 |
| 全量回测速度 | 可交互 | 向量化内核优先，不支持时回退事件驱动 | 部分达成（市值策略走事件驱动） |
| 数据准确性 | 无未来函数 | 财务/分红按公告日 as-of 加载 | 达成 |
| 多端适配 | 浏览器 + 手机 | Streamlit 响应式 + 卡片式 HTML 组件 | 达成 |
| 国际化 | 中/英切换 | `I18N` 字典 + URL `?lang=` 持久化 | 部分达成（部分页面文案仍为硬编码中文） |
| 可测试性 | 关键逻辑有回归测试 | 市值策略调仓/估值/覆盖日期 12 项用例；成本/绩效/缓存仍缺 | 部分达成 |
| 安全 | 凭据不入库 | 部署脚本仍硬编码 NAS 凭据 | **未达成** |

## 3. 范围

### 3.1 范围内（In Scope）

- 日线级回测（前复权），T 日信号 / T+1 开盘成交。
- 函数式选股策略与有状态策略类（如市值策略的每日再平衡）。
- 全 A 股 + ETF 的日线、季报财务、分红、实时快照。
- 多源新闻聚合（境内 4 源 + 境外 9 个 RSS 源），标题哈希去重、最早来源优先。
- 交易成本模型：佣金 / 印花税 / 过户费 / 滑点 / 冲击成本。
- 单容器部署与 NAS 增量部署脚本。

### 3.2 范围外（Out of Scope）

- 实盘下单、券商对接、资金托管。
- 分钟级 / Tick 级回测。
- 多用户、权限、计费。
- 衍生品（期货、期权）与港股/美股个股回测（全球市场仅做展示）。

| 风险 | 影响 | 概率 | 应对 |

| 单容器故障 | 中：服务不可用 | 中 | `restart: unless-stopped` + healthcheck；SQLite 文件可备份恢复 |
| 明文凭据 | 高：内网被入侵 | 高 | P0-3 外置；轮换密码；限制 NAS SSH 来源 |
| SQLite 写并发 | 低：偶发 `database is locked` | 低 | WAL 模式；写操作集中在 Worker；未来可加写重试 |

## 9. 关键决策记录（ADR）

| 编号 | 决策 | 原因 | 代价/约束 |
|---|---|---|---|
| ADR-001 | 单容器双进程（`entrypoint.sh` 拉起 Worker + Streamlit） | NAS 上零编排成本 | 两进程共享容器资源；Worker 崩溃会拖累应用 |
| ADR-002 | SQLite + WAL 作为唯一存储 | 单机、零运维、文件级备份 | 不适合高并发写；备份需处理 WAL |
| ADR-003 | Streamlit 作为 UI | 开发速度快、单文件可交付 | 交互模型受限；需 HTML 组件补足实时刷新 |
| ADR-004 | 事件驱动 + 向量化双引擎 | 前者语义完整，后者速度快约 70 倍 | 两套实现需保持口径一致；市值策略只能走事件驱动 |
| ADR-005 | 浏览器直连东财行情 | 绕过后端轮询瓶颈，延迟 1–2 秒 | 依赖第三方接口；跨域与字段变更风险 |
| ADR-006 | 财务/分红按公告日 as-of | 消除未来函数 | 数据覆盖早期区间时策略会退化，需明确提示 |
| ADR-007 | 缓存键版本化（`v14` / `m1`） | 逻辑修复后旧结果必须失效 | 每次语义变更都要手动升版本并记录 |
| ADR-008 | 调仓只依据单标的自身偏离 | 避免其他标的涨跌连带触发反向调仓 | 需要维护单标的建仓基准与目标市值 |

## 10. 完成定义（DoD）

一个改动只有同时满足以下条件才算完成：

1. **功能**：目标页面可操作，失败路径有明确提示，不吞异常。
2. **数据**：写入幂等；重复执行不产生重复行；数据缺口能被覆盖索引正确识别。
3. **回测**：影响结果的改动必须升缓存版本；旧缓存不得被复用。
4. **验证**：本地能跑通；涉及生产的改动在 NAS 上 `py deploy_update.py --check` 通过；关键逻辑有回归用例（P0-1 完成后强制）。
5. **文档**：按 `docs/README.md` 第 5 节的维护规则同步对应章节。

# 04 · 策略规格说明

> 文档基线：2026-11-17
> 代码：`backtest_engine.py`（函数与类）、`fast_backtest.py`（向量化实现）
> 数据口径：前复权日线；财务/分红按公告日 as-of

---

## 1. 通用交易约定

| 项 | 规则 |
|---|---|
| 信号时点 | T 日收盘后选股 / 产生信号 |
| 成交时点 | T+1 开盘价撮合，避免前视偏差 |
| 选股频率 | 函数式策略为**周频**：每周第一个交易日 |
| 持有期 | 默认 5 个交易日，到期卖出 |
| 涨停退出 | 持仓期间单日涨幅 ≥ `limit_up_pct`（默认 9.5%）时卖出 |
| 买入数量 | 函数式策略按可用现金 / `top_n` 等分，100 股取整，至少 100 股 |
| 有状态策略 | 每日都有全市场快照，自行决定买卖与数量（如市值策略） |
| 涨跌停不可成交 | **已建模**：买入遇涨停放弃，卖出遇跌停/停牌顺延到下一可卖日；板块 10% / 20% / 30%，ST 按日期分段（见第 8 节） |
| 停牌 | 当日无行情行：买入放弃，卖出顺延；引擎记录拦截次数 |

因子（`add_factors`）：

- `ret_5 / ret_20 / ret_60`：收盘价 5/20/60 日涨跌幅（%）
- `above_ma20 / above_ma60`：收盘价是否高于对应均线
- `cap_yi`：收盘价 × 流通股本 / 1e8（亿元）
- `turnover_pct`：换手率 × 100
- `vol_expand`：成交量 > 5 日均量 × 1.5
- `limit_up`：单日涨幅 ≥ 9.5%（因子列，固定阈值；引擎退出阈值可配）

## 2. 成本模型

`CostModel` 默认值，可在「参数设置 → 交易成本」修改，并参与回测缓存键：

| 项 | 默认 | 计算方式 |
|---|---|---|
| 股票佣金 | 0.0001154（万 1.154） | 成交额 × 费率，双边，单笔最低 1 元 |
| ETF/LOF 佣金 | 0.0001（万 1） | 成交额 × 费率，双边，单笔最低 0.2 元 |
| 印花税 | 0.0005（0.05%） | 成交额 × 费率，仅卖出；ETF/LOF 免征 |
| 过户费 | 0.00001 | 成交额 × 费率，双边 |
| 滑点 | 0.001 | 买入价 × (1+滑点)，卖出价 × (1−滑点)，单边 |
| 冲击成本 | 阈值 5% | 订单额/当日成交额 > 5% 时，`成交额 × ratio^1.5` |

可转债（沪万0.44 / 深万0.8）不在本平台回测范围内：数据层只采集股票与场内基金日线。

## 3. 绩效指标定义

`calc_performance` 输出 20 项指标，核心定义：

| 指标 | 公式/口径 |
|---|---|
| 总收益 | `期末/期初 − 1` |
| CAGR | `(期末/期初)^(1/年数) − 1`，年数 = 自然日/365.25 |
| 最大回撤 | 资金曲线相对历史高点的最大跌幅 |
| 夏普 | 日收益均值 / 日收益标准差 × √252，无风险利率 = 0 |
| 索提诺 | 日收益均值 / 下行波动率 × √252 |
| 卡尔玛 | CAGR / |最大回撤| |
| 日胜率 | 日净值上涨天数 / 总天数 |
| 涨停命中率 | 卖出原因 = `limit_up` 的交易数 / 总交易数 |
| 盈亏比 | 平均盈利 / 平均亏损（绝对额） |
| 最大连亏 | 连续下跌的最长交易日数 |
| 最大回撤持续 | 净值处于水下（dd < 0）的最长连续交易日数 |
| 日均换手 | (总买入额 + 总卖出额) / 交易日数 / 平均账户市值 |
| 成本占比 | 总交易成本 / 总成交金额 |

## 4. 策略一：小市值轮动·戴维斯双击

- 实现：`select_smallcap_rotation`（函数式，已注册向量化实现）
- 定位：小市值 + 高成长 + 低估值 + 财务健康 + 趋势确认
- 默认持仓：函数默认 3 只；界面由全局「持仓数」`top_n` 控制（默认 5）
- 周频调仓，持有 5 天

### 4.1 选股条件

| 维度 | 条件 | 参数（默认） |
|---|---|---|
| 市值 | `cap_yi ≤ cap_max` | `cap_max=30` 亿 |
| 动量 | `ret_20 ≥ 5%` | `ret_20_min=5.0` |
| 中期动量 | `ret_60 ≥ 0%` | `ret_60_min=0.0` |
| 趋势 | 收盘价 > MA20 且 > MA60 | `require_ma20/ma60=True` |
| 换手 | 3% ≤ 换手率 ≤ 20% | `turn_min=3.0`，`turn_max=20.0` |
| 量能 | 成交量 ≥ 5 日均量 × 0.8 | `volume_ratio_min=0.8` |
| 成长 | 净利同比 ≥ 20%，营收同比 ≥ 10% | `profit_yoy_min=20`，`revenue_yoy_min=10` |
| 估值 | `0 < PE_ttm < 所属行业中位 PE` | — |
| 财务健康 | 资产负债率 ≤ 70%，商誉/净资产 ≤ 30% | `max_debt_ratio=70`，`max_goodwill_ratio=30` |
| 竞争力 | ROE ≥ 行业中位 ROE | — |

### 4.2 评分与排序

```
score = ret_20 × 0.35 + ret_60 × 0.15
      + (cap_max − cap_yi)/cap_max × 20 × 0.10
      + turnover × 0.10
      + min(profit_yoy, 200) × 0.15
      + min(roe, 30) × 0.10
      + (PE > 0 ? 50/PE × 5 : 0)
```

取分数最高的 `top_n`（默认 3）。

### 4.3 数据依赖与退化

- 依赖 `daily_bar` + `fundamental`。
- `fundamental` 无可用数据（回测早期）时，**自动退化为纯动量选股**，只保留行情条件。
- PE 优先用财务表的 `pe_ttm`，缺失时用“当日收盘价 ÷ 当时可见的 EPS（按季度折算 TTM）”估算。
- 行业 PE/ROE 中位数由选股日截面按行业实时计算。

## 5. 策略二：动量+均线+小市值

- 实现：`select_momentum`（函数式，已注册向量化实现）
- 定位：动量过滤追高，均线确认趋势
- 默认持仓：函数默认 3 只；界面由全局「持仓数」`top_n` 控制（默认 5）
- 周频，持有 5 天

### 5.1 选股条件

| 条件 | 参数（默认） |
|---|---|
| `ret_20 ≥ 5%` | `ret_20_min=5.0` |
| 收盘价 > MA20 | `require_ma20=True` |
| `0 < cap_yi ≤ 200 亿` | `cap_max=200` |
| 1% ≤ 换手率 ≤ 15% | `turn_min=1.0`，`turn_max=15.0` |

排序：按 `ret_20` 降序取 `top_n`。

### 5.2 设计意图

来自早期回测结论：**命中率 ≠ 赚钱**。纯小市值+高换手命中率更高，但追高后回撤大；动量与均线层的作用是过滤“涨停后跌回去”的标的。

## 6. 策略三：市值策略（有状态类）

- 实现：`MarketCapStrategy`（继承 `BaseStrategy`，**不走向量化引擎**）
- 定位：在 15–200 亿主板中选小市值，75% 资金等比例持有，按单标的偏离动态再平衡
- 默认持仓：类默认 3 只；界面同样由全局「持仓数」`top_n` 控制（默认 5），指定 `universe` 时等于池内标的数
- **每日检查**

### 6.1 建仓规则

1. 股票池过滤（`_filter_market_cap_universe`）：
   - 排除创业板（30 开头）、科创板（688 开头）、北交所（数据层已排除）；
   - 市值在 `[cap_min, cap_max]`，默认 15–200 亿；
   - 上市 ≥ `min_listed_years`（默认 3 年，按首根 K 线估算）；
   - MA30 上升（`MA30(t) > MA30(t − lookback)`，lookback=5）；
   - 不良标的剔除（见 6.4）；
   - 按市值从小到大排序。
2. 空仓或换股后仓位不足时补足槽位，新标的按等比例目标市值建仓。
3. 总投入 = 账户总市值 × `weight_fraction`（默认 75%），剩余现金留存。

### 6.2 换股规则

- 持仓标的 MA30 拐头向下（`MA30(t) ≤ MA30(t − lookback)`）时整仓卖出，腾出槽位。
- 新入选标的同样要求 MA30 未走弱。
- `ma30_exit=False` 可关闭 MA30 退出。

### 6.3 调仓方式（`rebalance_mode`，2026-11-17 新增）

| 方式 | 规则 | 换手特征 |
|---|---|---|
| `deviation`（旧逻辑） | 6.3.1 的偏离度再平衡：单只市值偏离 ≥ 4% 或仓位偏离 ≥ 5%（取绝对值）即补/减仓，每日检查 | 日均换手 3.66%，但单笔金额小；**下跌补仓、上涨减仓**，等于持续削掉赢家 |
| `topk_drop`（默认，借 Qlib Topk-Drop） | 持仓在候选池中排名跌出 `top_n + rank_buffer` 才换出；只补空槽位；**不做**偏离度再平衡 | 日均换手 3.96%，单笔为整仓进出；成交笔数约为旧的 1/4 |

`topk_drop` 细节：

```
ranked   = 当日通过全部过滤的候选，按市值升序（越小越靠前）
keep     = top_n + rank_buffer        # 默认 5 + 2 = 7
换出：持仓不在 ranked 中，或排名 > keep → 卖出（原因 rank_drop）
买入：空槽位按 ranked 顺序补足；单只目标市值 = 总市值 × weight_fraction / top_n
现金：换出回款当日可用于买入（卖单先于买单撮合）
```

MA30 清仓（6.2）在两种模式下都生效，优先级高于排名换出。

指定标的池（`universe`，如单只 ETF 验证）时没有「排名」概念：排名换股分支不执行，`topk_drop` 自动退化为偏离度再平衡。2026-11-18 修复了此前该组合下两条分支都不走、导致建仓后一路持有到 MA30 走弱的问题。

对照回测（2023-01-01 ~ 2026-11-16，初始 100 万，详见 06 文档）：`deviation` +2.20% / Sharpe 0.14；`topk_drop` buffer=2 +27.05% / 0.39；buffer=4 +65.24% / 0.69。收益差异的主因不是成本（成本占初始资金 6.3% vs 9.6%），而是旧逻辑「跌了补、涨了减」持续反向操作持仓。

### 6.3.2 周线 MA30 的预计算口径

逐日对每只标的 `resample("W-FRI")` 在 5000 只 × 900 天规模下不可接受，因此改为一次性预计算（`build_ma30_cache` + `ma30_slope_up`）。必须遵守的口径：

- 周标签是「该周周五」，当日所在周的标签可能**晚于**当日；查当前周要用 `searchsorted(side="left")`，不能用 `side="right"-1`；
- 已走完的周用该周最后一个交易日收盘价；**当日所在的未走完周必须用当日收盘价**替换该周收盘，否则 MA30 会滞后最多 4 个交易日；
- 当日晚于该股最后一条行情时（停牌/退市），退回最后一个完整周；
- 周数 < `30 + lookback` 时返回 `None`，调用方按「不做判断」放行，与旧逻辑一致。

该口径有逐日对齐的回归用例（`Ma30CacheTest.test_matches_per_day_resample_on_every_day`）。

### 6.3.1 偏离度再平衡（`deviation` 模式语义，2026-11-16 修复）

每日检查，只调整**自身偏离超阈值**的标的：

```
单只目标市值 = 账户总市值 × weight_fraction / 当前持仓数
自身价格/市值偏离 cap_dev：优先用 cap_yi，ETF 无市值时用价格
   base 为建仓/上次调仓的成交基准（on_trade 用实际成交价重置）
自身仓位偏离 mv_dev = 当前持仓市值 / 单只目标市值 − 1

触发条件：|cap_dev| ≥ cap_change_threshold(默认 4%)
        或 |mv_dev| ≥ rebalance_threshold(默认 5%)

方向：当前市值 < 目标 → 补仓；> 目标 → 减仓
```

硬约束：

- **不得**用多标的平均市值作为判断依据（旧实现的错误，会因其他标的涨跌连带反向调仓）；
- 先生成卖单回款，再生成买单；买单数量受可用现金约束，现金不得为负；
- 单笔差异不足 100 股时跳过；数量按 100 股取整；
- 全部订单走 `rebalance_orders`，T+1 开盘成交。

### 6.4 不良标的剔除（四项，各自可开关，默认开启）

| 过滤 | 判定 | 数据来源 |
|---|---|---|
| ST / *ST / 退市整理 | `fundamental.is_st = 1` | `fundamental` |
| 现金流背离 | `EPS > 0` 且每股经营现金流 < 0；Q1（0331）豁免 | `fundamental.ocf_per_share` |
| 营业外盈利 | 净利 > 0 但营业利润 ≤ 0，或（净利 − 营业利润）/ 净利 > 50% | `fundamental.operating_profit` |
| 长期不分红 | 近 `dividend_years` 个完整财年 + 当年均无现金分红；分红覆盖为空时自动跳过该过滤 | `dividend` |

无财务数据时**放行**（与既有退化约定一致），因此回测早期区间的过滤强度会自然下降。

### 6.5 参数表

| 参数 | 默认 | 含义 |
|---|---|---|
| `top_n` | 3 | 持仓槽位数（指定 `universe` 时等于池内标的数） |
| `cap_min / cap_max` | 15 / 200 | 市值范围（亿） |
| `weight_fraction` | 0.75 | 投入资金占总市值比例 |
| `cap_change_threshold` | 0.04 | 自身价格/市值偏离阈值（仅 `deviation` 模式） |
| `rebalance_threshold` | 0.05 | 自身仓位偏离阈值（仅 `deviation` 模式） |
| `rebalance_mode` | `topk_drop` | 调仓方式：`topk_drop` / `deviation` |
| `rank_buffer` | 2 | `topk_drop` 缓冲名次：排名跌出 `top_n+rank_buffer` 才换出 |
| `min_listed_years` | 3 | 最短上市年限 |
| `exclude_st` | True | 剔除 ST |
| `exclude_ocf_diverge` | True | 剔除现金流背离 |
| `exclude_nonop_profit` | True | 剔除营业外盈利 |
| `exclude_no_dividend` | True | 剔除长期不分红 |
| `dividend_years` | 3 | 分红检查财年数 |
| `ma30_lookback` | 5 | MA30 斜率回看天数 |
| `ma30_exit` | True | MA30 拐头向下是否清仓换出 |
| `universe` | None | 固定标的池；指定后跳过选股，仅做建仓/调仓（单标的验证用） |

### 6.6 单标的验证模式

设置 `universe=["sz159509"]`、`top_n=1`，策略跳过市值/财务选股，只在该标的上建仓与调仓，用于验证补仓/减仓方向是否符合预期。

## 8. 回测口径与局限

必须向使用者明示的局限性：

1. **已建模涨跌停不可成交，但仍无封单量**：按板块识别涨跌停价（主板 10%、创业板/科创板 20%、北交所 30%，创业板 2020-08-24 前 10%，主板 ST 2026-07-06 前 5%），T+1 开盘触板则买入放弃、跌停卖单顺延；无法模拟封单量与排队顺序，实盘成交率仍可能低于回测。
2. **未建模流动性冲击**：卖出顺延只处理涨跌停/停牌，未建模大单分批、盘口深度与滑点扩散。
3. **幸存者偏差**：标的池来自当前可获取的历史数据，退市标的覆盖不完整时收益可能高估。
4. **财务数据覆盖**：早期区间无财务数据时策略退化，前后期口径并不一致，跨期比较需谨慎。
5. **参数过拟合**：默认参数来自历史区间，换区间或换样本可能失效；应以 K 段稳健分（0.6×中位数 + 0.4×最差段）选参，并用滚动样本外验证 IS→OOS 退化率，不要只看整段区间冠军。
6. **抽样报告不等于全量结果**：`backtest_report.txt` 是 2026-11-12 的 198 只抽样报告（seed=42），不能作为当前全量结论。

> 策略结论一律以界面「最近回测」的资金曲线与逐笔交易为准，并记录参数、区间、数据日期。
